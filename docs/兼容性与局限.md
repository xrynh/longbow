# 兼容性与局限

写清楚"哪些情况我没试过"，比写"支持一切"有用。

## 1. 环境矩阵

| 组合 | 状态 |
|---|---|
| MC 26.1 / 26.1.2 + Fabric Loader 0.19.3 + Fabric API 0.155.2 | **已验证**（单人，多轮真机自测 34/34） |
| Iris 1.10.9 + ComplementaryUnbound 光影 | **已验证**（拖尾、星芒、白框、光球全部可见，无 `Missing program` 报错） |
| 关闭光影（原版渲染） | **已验证**（同样的管线在关闭光影时也走 `LIGHTNING`，表现一致） |
| 其他光影包 | **未验证**。理论上只要它不接管 `LIGHTNING` / `TRANSLUCENT_PARTICLE` 两条管线就没事 |
| 多人服务器 | **未验证**。需要服务端与客户端都装本模组 |
| 专用服务端（无客户端） | 机制部分能跑，但没有特效（客户端类不加载） |
| Forge / NeoForge | 不支持，只做了 Fabric |
| 其他 MC 版本 | 不支持。26.1 用 Mojang 官方映射，API 与 1.21.x 差异很大，没有向下兼容的打算 |

构建环境：JDK **25**、Gradle 9.7.1、Loom 1.18.4。低版本 JDK 编不过（源码用了 25 的语言特性/API）。

## 2. 光影相关的两个已知坑

### 2.1 本模组自己不会在光影下报错

所有世界空间特效都走 `RenderPipelines.LIGHTNING`，光球走 `TRANSLUCENT_PARTICLE`，
两条都在 Iris 的白名单里。光影开着时控制台**不应该**出现本模组的
`Missing program ... in override list`。

如果出现了，优先怀疑：管线被改回了 `DEBUG_*` 系列，或者光影包自己没实现那条管线。

### 2.2 F3 满屏蓝块不是本模组的 bug

现象：按 F3 之后世界里每个粒子外面套一个发光的青蓝色线框盒。

根因在 **polytone**（`polytone-fabric` 的 `ParticleHitboxDebugRenderer`）：它的静态块把
`polytone:particle_hitboxes` 塞进原版 `DebugScreenEntries` 的 DEFAULT/PERFORMANCE profile，
于是 F3 一开就给每个粒子画 `Gizmos.cuboid` 线框。而 `debug_filled_box` / `debug_lines`
不在 Iris 白名单里，于是画成一坨乱块。

需要注意的是 `Gizmos.*` 其实是**每帧都画**的（`LevelRenderer.addMainPass` 无条件
`finalizeGizmoCollection()`），跟 F3 无关——F3 只是让它显形。

关法二选一：

- 实例根目录的 `debug-profile.json` 里加 `"polytone:particle_hitboxes": "never"`
- 游戏里 `F3+F6` 打开调试项列表，把它设成 never

**注意**：在 `F3+F6` 里切换 DEFAULT/PERFORMANCE profile 会把 polytone 注入的那份 map
重新装回来，蓝块会复现。

## 3. 性能

| 项 | 量级 | 说明 |
|---|---|---|
| 拖尾 | 每点 12 条棱 × 1 个四边形 | 正常一箭几百到几千个点 |
| 拖尾队列上限 | 20000 个框 | 超了从最老的开始丢 |
| 光球 | 每颗 1 个四边形 | 每 tick 最多 28 颗，寿命 15 秒，最坏约 8000 颗 |
| 粒子组上限 | 16384 / 组 | 原版 `ParticleGroup` 的 `EvictingQueue`，超了淘汰最旧的 |
| 破坏 | 6000 方块/tick | 满蓄一次可能扫 4×4×8 区块，会持续几秒 |

满蓄力打一炮是最吃性能的场景：破坏队列 + 大量拖尾点 + 光球同时在场。
低配机器建议先打轻击档试试。

## 4. 已知缺陷

- **尾迹近距离会连成片**。每个点是 0.072 格的线框方块，贴到 1 格内看就是一条实心彩带，
  看得出是一串框而不是一段光带。想要"光带"得换成带贴图的条带，成本和风险都更高。
- **光球远处只是一个点**。0.08~0.13 格的球在 30 格外不到 2 像素，
  是"远处的小亮点"而不是"远处的球"。这是尺寸和可读性的直接矛盾，没找到更好的解。
- **星芒的屏幕尺寸恒定，世界尺寸不恒定**。极远处（封顶 2.6 格）和极近处（下限 0.18 格）
  都不是等比，纯看手感调的。
- **没有音效**。射箭、超载、爆炸全部沿用原版音效，没有专门做。
- **破坏不掉落东西**。是"逐方块挖掉"而不是爆炸实体，所以不掉落、没有爆炸粒子。
- **箭的拖尾靠补点**，4 格/tick 的快箭一 tick 补 28 个点，慢箭 10 个；
  极慢的箭（比如射进水里）点会很稀。
- **`despawn` 之后拖尾还在**。这是设计如此（要留 45 秒），但走远了会看到"无主的彩带"。

## 5. 没做的东西

- **神秘控制面板**：视频里那个枚举并批量删除实体的面板，没实现
- **时停模块**：禁止生物模拟但仍可射箭，没实现
- 视频里还有一些零碎效果（例如弓的特殊待机动画），只做了能看出效果的部分

## 6. 用的时候踩过的坑（给改代码的人）

- **26.1 没有 Yarn**，只有 Mojang 官方映射；Loom 固定 `1.18.4`，用 `1.18-SNAPSHOT` 会卡在依赖解析。
- **客户端拿不到实体 tag**。判断"是不是长虹箭"要用 `arrow.getOwner()` 是否手持弓，
  `ClientFxManager.isLongbowArrow` 里做了 30 秒 memo 兜底。
- **创造模式飞行靠 `Abilities.setFlyingSpeed`**，只改 `MOVEMENT_SPEED` 飞起来完全没感觉。
- **两个"持弓才有"的状态是按 tick 刷的**。任何测量/断言前先显式调一次
  `LongbowMod.applyHeldState(player)`，别指望"上一 tick 手里正好拿着弓"。
- **自测里的坐标会撞世界高度上限**。下界建筑上限 256，把玩家传送到 `groundY+6` 之后再 `+60`
  就 `setBlock` 静默失败，表现为"方块没消失"的假失败。该夹的夹住。
